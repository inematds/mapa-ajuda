Em resumo

O mapa-ajuda é um modelo pronto de central de ajuda para sites, cursos, comunidades e produtos. Em vez de uma lista de perguntas frequentes, o visitante clica no problema que tem agora e vê um caminho em etapas, com o link certo em cada uma. Serve para quem recebe sempre as mesmas dúvidas ou tem conteúdo espalhado em vários lugares. É uma página HTML só: para usar, basta editar um arquivo de texto com os seus caminhos e publicar em qualquer hospedagem.

O que é

Ajuda que mostra o caminho, não uma lista de artigos

Três ideias fazem o mapa funcionar melhor que um FAQ.

🧭 Um problema, um caminho

Os cartões são escritos como a pessoa pediria ajuda ("não encontro um conteúdo"). Um clique abre as etapas em ordem, na mesma página.

❓ Perguntas de corte

No ponto em que a maioria trava, uma pergunta de sim ou não manda de volta quem ainda não fez o pré-requisito. Menos dúvida repetida no suporte.

📄 Um arquivo só

Visual e lógica ficam no index.html. Textos, links e ilustrações ficam no config.js. Trocou o arquivo, trocou o mapa.

Como funciona

Do cartão ao link certo

Cada caminho é uma sequência de peças. O motor monta a trilha na horizontal no computador e em coluna no celular.

Escolhe o problema→ Abre o caminho→ Passo com link→ Pergunta sim/não→ Saída para outro caminho

Passo

Uma ação com um link. passo

Seta

O que leva ao próximo: "Não achou?", "Se sim". seta

Pergunta

Sim ou não, com um desvio para quem não está pronto. pergunta

Lista

Várias opções do mesmo nível, numeradas. lista

Saída

Leva a outro cartão e liga os caminhos. saida

Pré-requisitos

O que você precisa

Nada de instalar framework. Um editor de texto e um lugar para publicar.

Editor de texto

Qualquer um serve (VS Code, Notepad++, o do sistema). Você só edita o config.js.

# abrir a pasta no VS Code
code mapa-ajuda

Git (opcional)

Para copiar o modelo e publicar no GitHub Pages. Sem Git, baixe o ZIP pelo GitHub.

# conferir se está instalado
git --version

Hospedagem estática

GitHub Pages, Vercel, Netlify ou o servidor do seu site. Também abre direto no navegador.

# testar no computador
python3 -m http.server 8000
Guia de uso · passo a passo

Monte o mapa de ajuda do seu negócio

Seis passos, do download à página no ar.

1

Copie o modelo

Clone o repositório (ou use "Use this template" no GitHub, ou baixe o ZIP).

git clone https://github.com/inematds/mapa-ajuda.git meu-mapa
cd meu-mapa
2

Comece pelo exemplo genérico

O config.js que vem no repo é o do INEMA. Troque pelo exemplo em branco, que já traz comentários com todos os campos.

cp exemplos/config.vazio.js config.js
3

Escreva um caminho

Cada problema é um cartão. O fluxo é a lista de peças, na ordem em que aparecem. Texto aceita **negrito**.

{
  id: 'suporte',
  titulo: 'Algo deu errado',
  resumo: 'Erro, acesso ou cobrança.',
  icone: 'escudo',
  imagem: 'assets/suporte.webp',  // opcional
  fluxo: [
    { tipo: 'passo', rotulo: 'Mais rápido', tempo: 'Na hora', titulo: 'Busque na base de ajuda',
      link: { texto: 'Buscar', url: 'https://exemplo.com/ajuda' } },
    { tipo: 'seta', rotulo: 'Não achou?' },
    { tipo: 'pergunta', pergunta: 'Você já tem conta?',
      ramo: { rotulo: 'Se não', tipo: 'nao', titulo: 'Crie primeiro.', abrir: 'primeiros-passos' } },
    { tipo: 'seta', rotulo: 'Se sim', cor: 'sim' },
    { tipo: 'saida', pergunta: 'Ainda travado?', texto: 'Falar com uma pessoa', destino: 'contato' }
  ]
}
4

Coloque as ilustrações

Salve uma imagem por cartão em assets/ (WebP, 3:2, até ~100 KB) e aponte no campo imagem. A capa da página vai em capa. Sem imagem, o cartão mostra o ícone. Use a mesma linha visual em todas: mesma paleta, luz e fundo, sem texto dentro da imagem.

# converter uma imagem para WebP leve
ffmpeg -i arte.png -vf scale=960:-1 -q:v 80 assets/suporte.webp
5

Teste no computador

Abra o servidor local e clique em todos os cartões. Cada caminho tem endereço próprio: #suporte abre direto o caminho de suporte.

python3 -m http.server 8000  # abra http://localhost:8000/#suporte
6

Publique

Suba para o GitHub e ligue o Pages (ou arraste a pasta para a Vercel ou a Netlify). Não há build.

git add -A && git commit -m "meu mapa de ajuda" && git push
gh api -X POST repos/<usuario>/<repo>/pages -f 'source[branch]=main' -f 'source[path]=/'

Como escrever um bom caminho

Na voz de quem pede

"Preciso de ajuda com acesso", não "Suporte". A pessoa tem que se reconhecer no cartão.

De 3 a 5 etapas

Mais que isso, quebre em dois caminhos e ligue com uma Saída.

Uma pergunta de corte

No ponto onde a maioria trava. Quem não fez o anterior volta uma casa.

Um link por passo

E um verbo no botão: "Abrir", "Buscar", "Escrever".

Canais em ordem de velocidade

No suporte: o que responde na hora primeiro, pessoas depois, e-mail por último.

Nunca um beco sem saída

Todo caminho termina em outro caminho ou num canal humano.
