In short

mapa-ajuda is a ready-made help center template for websites, courses, communities and products. Instead of a list of frequently asked questions, the visitor clicks the problem they have right now and sees a path in steps, with the right link at each one. It suits anyone who keeps getting the same questions or has content scattered across many places. It is a single HTML page: to use it, just edit a text file with your own paths and publish it on any hosting.

What it is

Help that shows the way, not a list of articles

Three ideas make the map work better than an FAQ.

🧭 One problem, one path

The cards are written the way a person would ask for help ("I can't find a piece of content"). One click opens the steps in order, on the same page.

❓ Gate questions

At the point where most people get stuck, a yes-or-no question sends back whoever hasn't done the prerequisite yet. Fewer repeated questions to support.

📄 Just one file

Look and logic live in index.html. Texts, links and illustrations live in config.js. Swap the file, swap the map.

How it works

From the card to the right link

Each path is a sequence of pieces. The engine lays the trail out horizontally on a computer and in a column on a phone.

Picks the problem→ Opens the path→ Step with a link→ Yes/no question→ Exit to another path

Step

One action with a link. passo

Arrow

What leads to the next piece: "Didn't find it?", "If yes". seta

Question

Yes or no, with a detour for whoever isn't ready. pergunta

List

Several options on the same level, numbered. lista

Exit

Leads to another card and connects the paths. saida

Prerequisites

What you need

No framework to install. A text editor and a place to publish.

Text editor

Any one will do (VS Code, Notepad++, the one that comes with your system). You only edit config.js.

# open the folder in VS Code
code mapa-ajuda

Git (optional)

To copy the template and publish on GitHub Pages. Without Git, download the ZIP from GitHub.

# check that it is installed
git --version

Static hosting

GitHub Pages, Vercel, Netlify or your own website's server. It also opens straight in the browser.

# test on your computer
python3 -m http.server 8000
User guide · step by step

Build your business's help map

Six steps, from download to a live page.

1

Copy the template

Clone the repository (or use "Use this template" on GitHub, or download the ZIP).

git clone https://github.com/inematds/mapa-ajuda.git meu-mapa
cd meu-mapa
2

Start from the generic example

The config.js that comes in the repo is the INEMA one. Replace it with the blank example, which already has comments on every field.

cp exemplos/config.vazio.js config.js
3

Write a path

Each problem is a card. The fluxo is the list of pieces, in the order they appear. Text accepts **bold**.

{
  id: 'suporte',
  titulo: 'Something went wrong',
  resumo: 'Error, access or billing.',
  icone: 'escudo',
  imagem: 'assets/suporte.webp',  // optional
  fluxo: [
    { tipo: 'passo', rotulo: 'Fastest', tempo: 'Right away', titulo: 'Search the help base',
      link: { texto: 'Search', url: 'https://exemplo.com/ajuda' } },
    { tipo: 'seta', rotulo: 'Didn\'t find it?' },
    { tipo: 'pergunta', pergunta: 'Do you already have an account?',
      ramo: { rotulo: 'If not', tipo: 'nao', titulo: 'Create one first.', abrir: 'primeiros-passos' } },
    { tipo: 'seta', rotulo: 'If yes', cor: 'sim' },
    { tipo: 'saida', pergunta: 'Still stuck?', texto: 'Talk to a person', destino: 'contato' }
  ]
}
4

Add the illustrations

Save one image per card in assets/ (WebP, 3:2, up to ~100 KB) and point to it in the imagem field. The page cover goes in capa. With no image, the card shows the icon. Use the same visual style in all of them: same palette, light and background, no text inside the image.

# convert an image to lightweight WebP
ffmpeg -i arte.png -vf scale=960:-1 -q:v 80 assets/suporte.webp
5

Test on your computer

Start the local server and click every card. Each path has its own address: #suporte opens the support path directly.

python3 -m http.server 8000  # open http://localhost:8000/#suporte
6

Publish

Push to GitHub and turn on Pages (or drag the folder to Vercel or Netlify). There is no build.

git add -A && git commit -m "my help map" && git push
gh api -X POST repos/<usuario>/<repo>/pages -f 'source[branch]=main' -f 'source[path]=/'

How to write a good path

In the voice of whoever asks

"I need help with access", not "Support". The person has to recognize themselves in the card.

3 to 5 steps

More than that, split it into two paths and connect them with an Exit.

One gate question

At the point where most people get stuck. Whoever hasn't done the previous step goes back a square.

One link per step

And a verb on the button: "Open", "Search", "Write".

Channels in order of speed

In support: what answers right away first, people next, email last.

Never a dead end

Every path ends in another path or a human channel.
